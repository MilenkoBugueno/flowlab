# Formative Evaluation für Pilot 0

## Beobachtungscheckliste der Spielleitung

Je Punkt notieren: Zeitpunkt, konkretes Verhalten und gegebenenfalls verwendeter
Hinweis.

- Welche Datenquelle wird zuerst verwendet?
- Werden Beobachtung und Interpretation getrennt?
- Verbindet das Team mindestens zwei Artefakte?
- Wird hoher WIP ausdrücklich benannt?
- Wird die Warteschlange vor dem Systemtest erkannt?
- Wird hohe Auslastung automatisch als positiv behandelt?
- Entstehen persönliche Schuldzuweisungen?
- Welche Rolle oder Person dominiert die Diagnose?
- Wann verändert sich die Haupthypothese?
- Formuliert das Team eine quantifizierte oder zumindest gerichtete Prognose?

## Diagnose-Rubrik

Jede Dimension wird mit 0–2 bewertet.

| Dimension | 0 | 1 | 2 |
|---|---|---|---|
| Signale | keine relevanten Signale | einzelnes relevantes Signal | mehrere verbundene Flow-Signale |
| Evidenz | unbelegte Behauptungen | eine Datenquelle | mindestens zwei konsistente Quellen |
| Kausalität | Symptom oder Schuldiger | teilweise Wirkungskette | nachvollziehbare Mechanismenkette |
| Intervention | allgemeiner Wunsch | passende Maßnahme ohne Nebenwirkung | Maßnahme, Mechanismus und Nebenwirkung |
| Unsicherheit | absolute Behauptung | Unsicherheit erwähnt | Alternative und benötigte Evidenz benannt |

Die Rubrik dient im ersten Pilot ihrer eigenen Erprobung. Der Score ist kein
valider Kompetenznachweis.

## Abschlussfragen für Teilnehmende

1. Welcher Moment hat eure Sicht auf das Projekt am stärksten verändert?
2. Welche Information war hilfreich, welche fehlte?
3. Was wirkte realistisch beziehungsweise unglaubwürdig?
4. Welche Regel oder Anweisung war unklar?
5. Welche Erkenntnis könntet ihr in einem eigenen Projekt überprüfen?
6. Was sollte vor dem nächsten Run unbedingt geändert werden?

## Pilotentscheidung

Nach dem Run gemeinsam entscheiden:

- `keep`: funktioniert ohne Änderung,
- `change`: konkrete Änderung für Version 0.2,
- `remove`: trägt nicht zum Lernziel bei,
- `investigate`: benötigt weitere Evidenz.
