# Intervention: Das nächste Helios-Inkrement

Ihr dürft höchstens **zwei** Veränderungen einführen. Das Ziel ist nicht nur
Geschwindigkeit, sondern zuverlässiger Flow bei tragfähiger Qualität.

## A — Zusätzlicher Systemtester

Die Testkapazität steigt rechnerisch um etwa 20 %. Einarbeitung und zusätzliche
Koordination sind im ersten Monat erforderlich.

## B — WIP-Limit und Pull

Jedes Entwicklungsteam darf höchstens zwei aktive Features führen. Neue Arbeit
wird erst gezogen, wenn ein Feature integriert oder bewusst abgebrochen wurde.

## C — Swarming auf alter Arbeit

Wenn Test oder Integration blockiert sind, unterstützen ursprüngliche
Entwickler zuerst die Fertigstellung, bevor sie neue Features beginnen.

## D — Auslastungsziel von mindestens 98 %

Alle Funktionen planen ihre Kapazität vollständig aus. Leerlauf soll durch das
Vorziehen weiterer Features vermieden werden.

## E — Drei Monate Feature Freeze

Nach Projektstart werden keine neuen Kundenwünsche angenommen. Bereits
begonnene Features bleiben jedoch alle im Scope.

## Vor der Entscheidung dokumentieren

1. Welche Maßnahme oder Kombination wählt ihr?
2. Welchen Mechanismus wollt ihr verändern?
3. Wie verändern sich nach zwölf Wochen voraussichtlich WIP, Lead Time,
   Throughput und Fehleralter?
4. Welche unerwünschte Nebenwirkung erwartet ihr?
