# Pilot 0: Design und Scope

## Zweck

Pilot 0 prüft, ob eine Gruppe aus fragmentierten Projektdaten ein gemeinsames
Flow-Problem rekonstruieren kann und ob die Sequenz aus Diagnose, Theorie,
Intervention und Rückmeldung praktisch durchführbar ist.

Der Pilot ist eine **formative Designprüfung**, keine Wirksamkeitsstudie.

## Lernziel

Nach dem Pilot sollen Teilnehmende besser in der Lage sein,

1. hohen WIP und wachsende Warteschlangen in Projektdaten zu erkennen,
2. lokale Auslastung von End-to-End-Flow zu unterscheiden,
3. Beobachtung, Hypothese und Begründung auseinanderzuhalten,
4. eine Intervention samt erwarteter Wirkung und Nebenwirkung zu formulieren.

## Verborgene Projektlogik

Project Helios leidet primär unter zu viel gleichzeitig gestarteter Arbeit.
Software und Hardware starten neue Features, obwohl Integration und Systemtest
bereits überlastet sind. Der nahezu voll ausgelastete Systemtest kann
Schwankungen nicht abfedern. Arbeit wartet, Fehler werden spät entdeckt und
Rückfragen treffen Teams, die gedanklich bereits an anderen Features arbeiten.

Das Spiel enthält absichtlich eine plausible lokale Erklärung: „Wir brauchen
mehr Testkapazität.“ Sie ist nicht völlig falsch, erklärt aber allein nicht die
systemische Dynamik.

## Nicht im Scope

- vollständige diskrete Ereignissimulation
- Batchgrößen als eigenständiger Lernmechanismus
- organisationale Macht- oder Anreizsysteme
- belastbarer Vorher-Nachher-Wirksamkeitsnachweis
- Vergleichsgruppe
- Übertragung auf reale Unternehmensdaten

## Erfolgskriterien des Piloten

- Der Run ist in höchstens 120 Minuten durchführbar.
- Die Gruppe erkennt hohen WIP und die Testwarteschlange ohne direkte Erklärung.
- Mindestens zwei Datenquellen werden in der Diagnose verbunden.
- Die Gruppe formuliert vor der Rückmeldung eine überprüfbare Prognose.
- Moderator und Teilnehmende können benennen, was unklar oder unglaubwürdig war.
- Aus dem Run entstehen konkrete Änderungen für Version 0.2.

## Versionierungsregel

Jeder Run dokumentiert Commit-ID, Spieldatum, Teilnehmerzahl und alle
Abweichungen vom Ablauf. Während eines Runs werden Materialien nicht verändert.
